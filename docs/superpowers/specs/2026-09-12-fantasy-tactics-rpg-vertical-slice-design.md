# 奇幻像素战棋 RPG 垂直切片设计

- 日期：2026-09-12
- 状态：已确认（2026-09-12）
- 首发平台：Android 横屏
- 引擎：Unity 当前 LTS 版本
- 开发语言：C#
- 美术状态：程序使用占位素材，后续按固定规范替换

## 1. 项目目标

制作一款单机离线、像素风格的奇幻战棋 RPG 垂直切片。玩家可以自由探索一张小型半开放地图，与 NPC 对话、交易和接取任务，进行网格战棋战斗，通过随机装备和打造形成角色构筑，最终击败地牢首领并完成首版主线。

垂直切片的单周目长度为 20 至 30 分钟，目标是验证以下核心循环：

`探索获取资源 -> 战棋获胜 -> 获得随机装备 -> 搭配词条 -> 挑战更强内容`

首版必须完整、可测试、可存档和可安装，而不是只展示某个孤立系统。

## 2. 首版非目标

首版明确不包含：

- 联网、账号、云存档、多人联机
- 内购、广告和运营活动
- iOS 发布
- 手柄和 PC 正式发布
- 程序生成开放世界
- 大型无缝地图
- 多结局、阵营战争和复杂声望
- 偷窃、潜行、日程模拟和随机说服检定
- 装备耐久、强化失败和强化等级
- 玩家交易、拍卖行和仓库
- 完整配音和最终美术

这些内容只有在垂直切片通过验收后，才通过新的设计流程评估。

## 3. 世界与内容范围

### 3.1 世界观

首版采用剑与魔法奇幻题材。故事发生在边境山谷。村庄附近的遗迹重新活跃，地下墓穴中的亡灵开始威胁道路与农田。玩家从村庄出发调查事件，并最终击败墓穴首领。

### 3.2 地图结构

地图是一张手工制作、互相连通的半开放区域，包含：

- 边境村庄：安全区，包含商店、铁匠、旅店、任务 NPC 和新手教学。
- 灰木森林：初级敌人、采集点、游侠伙伴支线。
- 旧哨塔遗迹：精英敌人、宝箱、机关和地图事件。
- 地下墓穴：最终地牢、首领战和主线结局。

玩家可以自由前往已开放区域。道路封锁、事件门槛和敌人强度用于控制节奏，不设置不可见等级墙。探索内容包括宝箱、采集点、可调查物、任务地点和隐藏入口。

### 3.3 首版内容规模

- 1 名可创建主角。
- 2 名可招募伙伴。
- 3 个职业方向：战士、游侠、法师。
- 约 8 名有名字的 NPC。
- 1 条短主线、2 条支线。
- 4 种普通敌人、1 名精英、1 名首领。
- 约 8 场固定战棋战斗。
- 等级上限 10。
- 每个角色约 3 个主动技能和 2 个被动能力。
- 6 个装备槽。
- 约 20 件基础装备。
- 30 条随机词条。
- 4 个装备品质。

NPC 功能角色包括：村庄长者、铁匠、杂货商、旅店老板、游侠伙伴、法师伙伴、猎人、遗迹幸存者。最终名称和文本可在内容制作阶段调整，但其功能数量属于首版范围。

## 4. 核心游戏流程

1. 玩家创建角色并从战士、游侠、法师中选择职业。
2. 玩家在村庄接受主线教学任务并熟悉对话、交易和装备。
3. 玩家进入灰木森林和旧哨塔遗迹，完成战斗、支线和探索。
4. 玩家在探索过程中招募另外两名伙伴。
5. 玩家收集材料、装备和金币，在铁匠处打造或重铸装备。
6. 玩家进入地下墓穴，进行最终地牢战斗。
7. 击败首领后完成主线，展示垂直切片结算。
8. 通关后仍可继续探索、交易和挑战未完成支线。

## 5. 战棋战斗设计

### 5.1 队伍结构

玩家控制主角和最多 2 名伙伴，每场战斗通常为 3 对 3 至 6。主角选择一种职业后，两名伙伴固定为另外两种职业，保证队伍包含前排、远程和法术/控制角色。

职业职责：

- 战士：高生命与防御，使用击退、嘲讽和护盾保护队友。
- 游侠：高机动和单体输出，可以布置陷阱并利用地形。
- 法师：范围伤害、元素状态和控制，生命与护甲较低。

### 5.2 回合与行动

- 战斗在独立网格场景中进行。
- 第一回合开始前，按照速度从高到低生成固定行动顺序。
- 速度变化在下一轮重新计算行动顺序。
- 每个单位每回合可以移动一次并执行一次主要行动。
- 主动技能可能消耗法力或具有冷却时间。
- 单位不能穿过障碍或其他单位。
- 战斗回合、行动次数、技能冷却和状态持续时间都由战斗状态机统一管理。

### 5.3 地形与状态

首版地形包括：

- 平地：无特殊影响。
- 障碍：不可通行并阻挡远程直线攻击。
- 灌木：可通行，但阻挡远程直线攻击。
- 高地：从高地攻击时增加伤害。
- 泥地：降低实际移动距离。

首版状态包括燃烧、中毒、眩晕、减速、护盾和嘲讽。同名状态以明确规则刷新、叠加或覆盖，不允许无限叠层。所有状态必须提供剩余回合、来源和实际效果说明。

### 5.4 战斗目标与 AI

普通战斗的默认目标是击败全部敌人。首领战可以使用“击败首领”或“坚持若干回合”作为目标。

敌方 AI 使用行动评分选择移动位置、目标与技能，优先级为：

1. 完成当前战斗目标。
2. 避免本回合可预见的死亡。
3. 治疗或保护关键友方。
4. 击杀低生命目标。
5. 使用可命中最多有效目标的技能。
6. 在平分时使用固定顺序决策。

AI 不读取隐藏玩家数据，不使用不可预测的随机乱动。相同局面和随机种子必须产生相同决策。

### 5.5 胜负与结算

胜利后统一结算经验、金币、装备掉落、任务进度和 NPC 状态。战败不会永久删除角色或装备。玩家可以选择：

- 使用同一随机种子重试本场战斗。
- 读取战斗前的自动存档。

首版不使用永久死亡。伙伴在战斗结束时以至少 1 点生命恢复；若全队战败，则返回最近安全点或自动存档。

## 6. 角色成长

### 6.1 基础数值

首版只保留以下基础属性：

- 生命
- 法力
- 攻击
- 护甲
- 速度
- 暴击
- 抗性

伤害公式必须可测试、可解释并限制随机浮动。玩法优先级为站位、技能和装备搭配，而不是隐藏公式。

### 6.2 升级

- 等级上限为 10。
- 经验由全队共享。
- 每次升级自动提升生命、攻击、防御或速度中的固定属性。
- 在指定等级获得技能点。
- 技能点可以解锁或强化主动技能与被动能力。
- 非战斗状态缓慢恢复生命。
- 所有角色倒下后返回最近安全点。

## 7. 装备与随机词条

### 7.1 装备结构

每件装备由基础装备、物品等级、品质和随机词条组成。

装备槽：

- 武器
- 副手
- 头部
- 身体
- 饰品
- 靴子

品质与随机词条数量：

- 普通：0 条随机词条，只有基础属性。
- 精良：1 条随机词条。
- 稀有：2 条随机词条。
- 史诗：3 条随机词条。

史诗装备至少包含一条技能修正或触发类词条。武器和部分防具存在职业限制，其余装备可以自由搭配。首版不加入耐久度、强化等级和装备损坏。

### 7.2 词条类型

- 固定数值：生命、攻击、护甲、速度等。
- 百分比效果：暴击、元素抗性、治疗效果等。
- 技能修正：射程、范围、冷却、目标数量等。
- 触发效果：攻击附加状态、受击获得护盾、击杀恢复生命等。
- 条件效果：低生命时提高护甲，高地攻击附加伤害等。

同一件装备不能出现重复或完全互斥的词条。每条词条必须拥有明确的数值范围和适用装备槽。

例如“霜纹长剑”拥有基础攻击属性，并可能带有一条使普通攻击概率减速的“冰痕”词条，以及一条使“旋风斩”半径 +1 的技能修正。

### 7.3 掉落生成

掉落使用可复现随机种子，按以下顺序生成：

1. 根据敌人、地点和玩家等级确定物品等级范围。
2. 从对应掉落池抽取基础装备。
3. 根据权重抽取品质。
4. 根据品质抽取不重复词条。
5. 在词条允许的数值区间内生成最终数值。

玩家等级影响掉落等级，但不会让低等级基础装备完全失去价值。所有掉落生成器都必须接受注入种子，以便复现和自动化测试。

### 7.4 打造与重铸

铁匠支持：

- 使用材料打造指定基础装备，品质和词条随机。
- 分解装备获得材料。
- 锁定一条词条后重铸其余词条。
- 显示每条词条可能出现的数值范围。

锁定词条会显著提高金币和材料消耗。装备生成必须遵守品质强度预算，避免大量随机组合中产生明显破坏平衡的极端装备。

## 8. 背包与经济

背包装有容量上限，并提供按槽位、品质、装备状态和词条类型排序的功能。首版不做仓库。

金币来源包括战斗、任务和出售物品。主要消耗为购买装备、打造、重铸和任务物品。商店库存固定并随主线进度扩充，不设置每日刷新。

统一经济服务负责价格公式、买卖限制和货币变更。买入价高于卖出价，但必须向玩家清楚展示。任务物品和已装备物品不能按普通商品直接出售。

## 9. NPC、对话与任务

### 9.1 NPC 与对话

NPC 支持普通对白、条件对白、商店、任务和简单好感度。对话节点可以检查：

- 任务状态
- 持有物品
- 已完成事件
- NPC 好感等级

对话结果可以：

- 接受或推进任务
- 提交物品
- 开启商店
- 改变好感
- 设置世界事件标记

好感度只分为陌生、友好、信任三档，影响对白、商店折扣和少量任务结果。首版所有对话条件均为确定条件，不使用随机说服。

### 9.2 交易

商店由 NPC 库存、买卖价格修正和条件解锁组成。购买时检查金币和背包容量；出售时检查物品是否已装备、是否为任务物品以及是否允许出售。价格计算不得分散在 UI 或 NPC 脚本中。

### 9.3 任务系统

任务状态包括未接取、进行中、可提交、已完成和失败。支持以下目标类型：

- 击败指定敌人或数量。
- 收集并提交物品。
- 到达或调查指定地点。
- 与指定 NPC 对话并选择结果。

任务日志显示当前目标、已知地点和奖励。任务完成后记录永久标记，不能重复领取奖励。支线奖励以金币、材料、装备配方和新商店库存为主，避免独立任务装备挤占随机掉落价值。

## 10. 存档设计

游戏提供 3 个手动存档位和 1 个自动存档位。自动存档发生在：

- 进入区域
- 完成战斗
- 完成任务
- 打造装备
- 退出游戏
- 战斗开始前

存档内容包括角色、伙伴、背包、装备实例、任务、NPC 状态、地图事件、金币、世界时间和随机种子。

存档流程为：

1. 写入临时文件。
2. 校验内容和版本。
3. 校验成功后替换正式存档。
4. 保留上一份有效备份。

存档带版本号和迁移入口。若自动存档损坏，游戏保留上一份有效备份并明确提示玩家，不静默覆盖。游戏从后台恢复时重新校验当前状态。

## 11. 软件架构

### 11.1 总体分层

采用“静态内容定义 + 运行时状态 + 表现层”三层结构。

模块划分：

- `Core`：启动流程、场景切换、游戏状态、时间、随机种子、存档和基础接口。
- `Data`：物品、词条、技能、敌人、任务、对话等静态定义及内容目录。
- `World`：地图、交互、NPC、掉落物、区域切换、世界状态。
- `Battle`：网格、寻路、行动顺序、单位、技能、状态、AI 和胜负判定。
- `Inventory`：背包、装备实例、掉落生成、打造和重铸。
- `Narrative`：对话条件、任务状态、奖励和交易规则。
- `UI`：HUD、菜单、战斗界面、商店和对话界面。
- `Tests`：规则、生成器、存档和关键流程的自动化测试。

各模块使用独立程序集隔离。UI 与表现层不能直接修改角色数值，必须调用对应系统的公开接口。

### 11.2 数据边界

静态定义使用 Unity `ScriptableObject`，例如：

- `ItemDefinition`
- `AffixDefinition`
- `SkillDefinition`
- `EnemyDefinition`
- `QuestDefinition`
- `DialogueDefinition`

运行时只保存定义 ID、实例 ID、当前状态、随机种子和已生成结果。存档不保存场景对象引用。美术和地图资源通过内容 ID 与 Addressables 定位。

### 11.3 场景与流程

Unity 场景包括：

- `Boot`：加载配置、校验内容、初始化服务。
- `MainMenu`：新游戏、继续、设置。
- `World`：村庄和半开放地图。
- `Battle`：独立战棋场景。

UI 使用附加场景或预制体，不把核心规则绑在具体场景中。

世界遇敌时生成 `BattleRequest`，包含参战单位、战场、目标、随机种子和奖励上下文。战斗结束后返回 `BattleResult`，由世界系统结算经验、掉落、任务和 NPC 状态。

### 11.4 战斗实现边界

战棋使用自定义网格模型，Tilemap 仅负责显示。移动、占位、射程和寻路读取同一份战斗数据。技能执行流程为：

`施放器 -> 目标选择 -> 效果列表 -> 状态结算`

技能、状态和词条通过数据组合，新增内容时不修改核心循环。

### 11.5 输入

输入先转换成与设备无关的游戏命令，例如移动、确认、取消、查看和结束回合。首版使用虚拟摇杆和触控按钮，输入层不直接依赖鼠标或键盘。

## 12. UI 与移动端规格

- 首版只支持横屏。
- 适配安全区、刘海屏和不同宽高比。
- 战斗界面必须清楚展示行动顺序、当前单位、移动范围、技能范围、状态、目标预览和结束回合按钮。
- 商店、背包和铁匠界面支持筛选、排序和数值比较。
- 对话界面支持跳过已读文本，但首版不做完整历史记录。
- 世界探索使用虚拟摇杆和互动按钮；UI 不遮挡关键地图区域。

## 13. 素材规范

首版使用程序占位素材，但最终素材规格固定为：

- 世界地块：32×32 像素。
- 世界角色：32×48 像素，四方向移动。
- 战斗单位：64×64 像素，包含待机、移动、攻击、受击和倒下动画。
- NPC 头像：256×256 像素。
- UI 使用九宫格素材和统一缩放规则。

像素素材使用邻近采样，避免非整数缩放。所有角色、装备、技能和场景通过 ID 引用素材。替换最终美术时不应修改玩法代码和存档格式。

## 14. 技术约束与内容校验

### 14.1 平台约束

- Unity 使用当前 LTS 版本。
- Android 最低版本为 8.0（API 26）。
- 使用 IL2CPP 与 ARM64。
- 目标帧率为 60 FPS，低负载场景允许 30 FPS 下限。
- 战斗场景同时存在的单位不超过 12 个。
- 地图活动对象按区域加载并使用对象池。
- 首版不接入联网服务。

### 14.2 内容校验

游戏启动时执行内容校验：

- 重复 ID
- 缺失引用
- 非法数值
- 不可达任务目标
- 循环任务前置
- 无效技能效果
- 错误掉落池
- 词条与装备槽不兼容

开发构建遇到严重错误时阻止进入游戏并输出明确报告。正式构建跳过损坏内容、记录日志并尽可能保持主流程可运行。

### 14.3 文字与版本管理

游戏文字使用本地化键。首版只提供简体中文，但代码中不硬编码文本。Unity 工程启用文本序列化，并使用 Git LFS 管理图片、音频和字体。

## 15. 测试策略

### 15.1 编辑模式测试

覆盖：

- 伤害公式
- 状态叠加与移除
- 随机词条与品质权重
- 掉落种子复现
- 经济价格和交易限制
- 任务条件与奖励
- 存档序列化、损坏检测和迁移

### 15.2 游玩模式测试

覆盖：

- 回合流转
- 网格寻路和占位
- 技能选择与目标判定
- AI 决策
- 战斗结算
- 世界与战斗场景切换
- 对话、商店和任务关键流程

### 15.3 手工验收

每轮开发构建至少完成：

- 从新游戏开始并完成一场战斗。
- 完成一次装备掉落、装备、分解和重铸。
- 完成一次自动存档、退出和恢复。
- 完成一条任务并确认奖励只能领取一次。
- 在目标 Android 设备上运行 10 分钟稳定性测试。
- 检查安全区、分辨率切换、后台恢复和旋转锁定。

## 16. 垂直切片验收标准

- 玩家可以不看外部说明完成“探索 -> 战斗 -> 获取装备 -> 回城打造 -> 接任务 -> 击败首领”的完整循环。
- 三场连续战斗能够体现职业、站位、地形和技能差异。
- 同一件基础装备的多次掉落能够产生可感知差异。
- 玩家至少需要做一次“保留哪条词条、重铸哪条词条”的构筑决策。
- NPC 对话、交易和任务状态在存档后正确恢复。
- 战败后可以重试或读取自动存档，不永久损失进度。
- 中端 Android 设备目标为 60 FPS，低负载场景保持 30 FPS 以上。
- 每个开发阶段都能生成可安装 Android 包。
- 自动化测试、内容校验和 10 分钟稳定性测试全部通过。

## 17. 风险与应对

- 内容规模失控：所有新增功能必须说明是否属于垂直切片验收；超出范围的请求进入后续版本。
- 随机装备不可控：使用品质预算、词条权重、互斥规则和固定种子测试。
- 战棋 AI 不稳定：使用可解释评分和固定平分规则。
- Unity 移动端性能不足：限制同屏单位、使用对象池和 Addressables，并持续记录加载与帧率。
- 任务状态难以维护：任务、对话与世界事件全部使用 ID 和显式状态机。
- 占位美术与最终素材不一致：先冻结尺寸、动画状态、锚点和导入规范。
- 存档损坏：原子写入、校验、备份和版本迁移。
